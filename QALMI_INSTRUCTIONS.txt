05 | ONLINE / OFFLINE CONTRACT
====================================================================

OFFLINE MUST WORK:
- After the app has been loaded and the user has previously authenticated on that device, the cached app shell and previously available documents must open without a network connection.
- Users must be able to create, open, edit, format, search, import, and export supported local documents offline.
- Persist each edit locally before showing it as saved. Distinguish “Saved on this device” from “Synced to cloud”.
- Queue document edits, comments, and supported metadata changes safely. Show pending, syncing, synced, and failed states per document.
- Reconnect automatically, retry safely, and avoid duplicated or lost edits. Use Yjs for concurrent document content rather than last-write-wins replacement.
- Warn about storage limits, persistence denial, and recovery/backup needs. Provide local export even when the server is unavailable.

ONLINE MUST WORK:
- Real sign-in, server-side access checks, invitations, share permissions, live co-editing, collaborator presence, cloud storage, and cross-device history must use a functioning backend.
- Live collaboration must be verified with at least two separate authenticated browser sessions.
- Handle expired sessions, revoked permissions, rejected updates, network drops, and server failures visibly and safely.

Do not promise first-run offline sign-in, instant cross-device sync without a server, or unlimited browser storage. Never rely only on `navigator.onLine`; test actual requests and collaboration socket state.
